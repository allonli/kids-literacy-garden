## 2026-09-16 新增：家长中心删除单个汉字

本节使用独立 SQLite 测试数据库与真实 Brave 浏览器，准备两个都包含目标汉字的学习账户，并记录删除前的完整状态。`tests/accounts-browser.mjs` 已包含删除回归；正式学习记录不用于删除验证，下面各节说明实际覆盖范围。

### 删除入口、取消与确认

1. 从首页进入“家长中心”，在汉字列表找到目标字，看到该行的“删除”按钮。
2. 点击“删除”，确认窗口明确显示目标字，并说明该字的拼音、组词、学习记录及今日/周末清单将从当前账户移除，其他账户不受影响，重新添加不会恢复原记录。
3. 取消确认，检查字仍在列表，资料、进度、历史和清单均未变化，页面可以继续操作。
4. 再次点击并确认，目标字从列表消失，显示删除成功提示；等待“已永久保存”，刷新后搜索该字仍无结果。
5. 使用另一个测试字，从家长中心打开详情，点击“删除这个字”，分别检查取消和确认。取消后详情保留；确认后详情关闭，列表同步移除并显示反馈。
6. 进入普通今日学习、复习和周末详情，确认没有单字删除入口，仍可正常学习。
7. 失败恢复：尚未确认可直接取消；确认删除后需要该字时用家长中心的添加功能重新添加，原记录不恢复。不要通过清空账户恢复单个汉字。

验收结果：真实浏览器在家长中心列表和详情分别取消删除，API 完整响应与删除前一致，详情取消后仍打开。详情确认删除山后弹窗关闭、列表移除；后续重新添加再从列表确认删除也成功。确认文本实际检查了当前账户、其他账户不受影响及原记录不恢复。刷新后周末与今日列表均不再显示山。普通学习详情不提供删除由可选回调的组件接线和原流程回归覆盖，未逐一打开所有复习详情检查。

### 关联数据清理、账户隔离与重新添加

1. 在账户 A 删除目标字后，进入今日列表和周末清单，确认该字从待学习、稍后复习及周末选字中移除，数量与剩余字一致。已完成队列和历史记录通过测试 API/SQLite 读回核对，不能残留该字 ID。
2. 检查账户 A 的其他字及设置，确认未被修改。返回首页切换到账户 B，确认同一个字的资料、阶段、历史、今日队列与周末清单保持删除前的值。
3. 切回账户 A，在家长中心“添加新学的字”输入刚删除的汉字并添加。确认该字重新出现并从待学习开始，原手动编辑和历史不恢复，也不自动加入原来的周末清单或已完成队列。
4. 等待永久保存后刷新，再核对账户 A 的重新添加结果和账户 B 的原进度。
5. 失败恢复：查不到目标字时先确认当前账户与搜索条件；误删后可重新添加学习，需要的拼音和组词可重新编辑。

验收结果：删除已编辑山后，真实 API 读回确认该字条目、历史、周末和今日队列引用移除，其他字条目与删除前一致；原账户完整响应保持不变。真实页面进入周末清单，空清单打印禁用，进入今日列表无山。重新添加山后从待学习开始，学习计数为零、原手动拼音和组词不恢复，今日列表可再次学习。单元和生产 API 测试进一步覆盖三个今日队列同时存在引用、空状态保存与严格按 ID 删除。
