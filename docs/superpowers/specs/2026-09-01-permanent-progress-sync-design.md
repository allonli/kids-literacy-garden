# 学习进度永久保存与跨设备同步设计

## 目标

把现有浏览器内的学习进度安全迁移到阿里云服务器，并在手机、平板和电脑之间同步同一个孩子的进度。同时优化答题节奏：读音完成后点击“会”，立即进入下一个字，不再等待成功提示倒计时。

本设计优先保证两件事：现有学习进度不能丢失，任何旧设备都不能用空数据覆盖已保存进度。

## 范围与边界

本次包含：

- 使用一个家庭码登录同一个孩子的学习空间。
- 将完整学习状态保存到服务器 SQLite 数据库。
- 保留现有本地缓存，并在首次登录时迁移旧进度。
- 跨设备同步、离线待同步、版本冲突保护和手动重试。
- 显示“保存中”“已永久保存”“网络断开，等待同步”等状态。
- 答对后立即进入下一张卡；答错仍进入不会的字复习卡并自动读音。
- 数据库独立于程序发布目录，提供每日备份和发布前备份。

本次不包含：

- 多个孩子或多家庭账号管理。
- 短信、邮箱、第三方账号登录。
- 多设备同时编辑时的逐字段自动合并。
- 在网页中下载、编辑或恢复数据库备份。
- 改变现有学习阶段、连续答对升级规则和复习间隔。

## 用户流程

### 原设备首次迁移

1. 家长在当前保存着学习进度的浏览器打开网站。
2. 网站继续读取现有 `kids-literacy:v1` 本地数据，不清除也不改名。
3. 家长输入部署时生成的六位数字家庭码。
4. 若服务器尚无学习进度，网站把本地完整状态原样上传，服务器原子写入为第 1 版。
5. 上传成功后显示“旧学习进度已永久保存”，并继续保留本地副本。
6. 页面刷新后从服务器读取同一进度，并更新本地缓存。

首次迁移必须由保存着旧进度的原设备完成。若服务器为空且当前浏览器没有旧进度，页面不得自动创建空进度，而是提示“请先在原来学习的设备上登录并保存进度”。家长确认确实没有旧进度时，才可通过二次输入家庭码并确认“创建全新进度”来初始化，避免误操作覆盖迁移机会。

### 日常学习与保存

1. 页面先用本地缓存立即显示内容，再向服务器检查最新版本。
2. 每次新学、复习判断、撤销、设置或汉字列表发生变化时，先同步写入本地缓存，界面立即响应。
3. 前台把最新完整状态和当前服务器版本异步上传。
4. 上传期间显示“保存中”；成功后显示“已永久保存”。
5. 网络失败时显示“网络断开，等待同步”，保留最新待同步快照；网络恢复、页面重新可见或家长点击“重试”时再次上传。

### 新设备使用

1. 家长输入同一个家庭码。
2. 网站读取服务器最新进度，并写入该设备的本地缓存。
3. 家长可以核对各阶段数量、设置和学习记录，确认与原设备一致。

## 答题交互

- 浏览器正在播放当前字读音时，继续禁止跳转和提交，防止下一张卡显示后仍播放上一个字。
- 读音结束后，点击“会”立即完成状态变更并显示下一张卡；最后一张则立即进入本轮完成页。
- 不再为答对保留 650 至 700 毫秒的反馈等待，也不依赖服务器保存完成后再跳转。
- “撤销上一步”继续保留；进入下一张后仍可撤销最近一次判断。
- 点击“不会”或“再学一下”仍进入不会的字复习卡，该卡自动播放读音，并保留“我学好了，下一个”。
- 若后台保存失败，孩子可以继续当前学习；顶部保存状态和重试入口负责提示家长处理。

## 系统架构

### 组成

- Next.js 页面继续负责学习界面和本地缓存。
- 同源 API 负责家庭码登录、读取进度、首次迁移和版本化保存。
- Node.js 内置 SQLite 驱动负责持久化，避免额外的原生依赖安装。
- 阿里云系统服务继续运行网站；数据库位于独立持久化目录。

服务器目录：

- 数据库：`/var/lib/kids-literacy/progress.sqlite`
- 每日备份：`/var/backups/kids-literacy/`
- 应用：`/opt/kids-literacy-garden`

应用发布和回滚只替换应用目录，不移动、不删除数据库目录。

### 数据模型

`progress` 表只保存当前家庭的一条权威进度：

| 字段 | 用途 |
| --- | --- |
| `family_id` | 固定家庭标识，唯一键 |
| `state_json` | 完整学习状态 JSON |
| `revision` | 单调递增的服务器版本号 |
| `updated_at` | 最后成功保存时间 |

`device_sessions` 表保存已登录设备：

| 字段 | 用途 |
| --- | --- |
| `token_hash` | 随机设备令牌的 SHA-256 摘要 |
| `family_id` | 所属家庭 |
| `created_at` | 登录时间 |
| `last_seen_at` | 最后访问时间 |
| `expires_at` | 失效时间 |

家庭码本身不写入数据库、不写入浏览器存储和日志。部署时生成六位数字家庭码，服务器环境变量只保存带随机盐的 `scrypt` 哈希。登录成功后生成随机设备令牌；明文仅存在于 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie 中，数据库只保存摘要。设备登录有效期为 180 天。

### API

- `POST /api/auth/login`：校验家庭码，创建或刷新设备会话。
- `GET /api/progress`：返回 `empty` 或 `{ state, revision, updatedAt }`。
- `POST /api/progress/migrate`：仅在服务器为空时原子写入旧本地状态；重复请求返回当前服务器结果，不覆盖。
- `PUT /api/progress`：接收 `{ state, baseRevision }`；仅当 `baseRevision` 等于当前版本时写入并将版本加一。

写接口只接受同源请求，并校验请求体大小、状态格式和状态版本。登录接口按来源地址限制为 10 分钟最多 5 次失败尝试。日志只记录接口结果、版本号和时间，不记录家庭码或完整学习内容。

## 数据迁移与兼容

现有本地存储键 `kids-literacy:v1` 是迁移源，也是离线缓存，必须一直保留。新增加 `kids-literacy:sync:v1`，只保存服务器版本号、待同步标记、最后成功同步时间和提示状态。

迁移内容必须是完整状态，包括：

- 每个字的学习阶段、连续答对次数和下次复习日期。
- 已掌握、每两周、每周、待复习和待学习状态。
- 家长新增及隐藏的字词。
- 每次学习数量、需要连续答对几次等家长设置。
- 学习历史、撤销所需状态及现有数据版本字段。

迁移采用数据库事务和唯一进度行，保证只有第一次成功写入。两台设备同时尝试迁移时，第一台成功后，第二台只能读取服务器数据，不能覆盖它。

## 同步与冲突规则

客户端始终维护一个已确认的 `revision`：

1. 本地变更后，把最新完整状态写入 `kids-literacy:v1`，并把它标记为待同步。
2. 上传携带 `baseRevision`。
3. 服务器版本相同则写入、版本加一并返回新版本；客户端清除待同步标记。
4. 服务器版本更高则返回 `409 Conflict`，绝不接受旧版本覆盖。
5. 客户端遇到冲突后拉取服务器状态，将冲突前的本地快照继续留在本地同步元数据中用于诊断，但界面采用服务器最新进度，并提示“另一台设备已有更新，已载入最新进度，请重新完成刚才的操作”。

离线期间只需保存“最新完整快照”，不逐条排队重复操作。恢复网络后一次上传最新快照。为减少同一设备连续操作产生冲突，上传按顺序串行执行；前一个上传期间出现的新变化合并到下一次最新快照。

页面首次打开、浏览器触发 `online` 事件、标签页从后台恢复可见时，都会检查服务器最新版本。若本机没有待同步变化，直接采用服务器新版本；若本机有待同步变化，则先按版本规则上传，冲突时执行上述保护流程。

## 保存状态界面

页面顶部提供紧凑的保存状态，不遮挡孩子的主要操作：

- `保存中…`：本地已保存，正在上传。
- `已永久保存`：服务器已确认，可附带最后保存时间。
- `网络断开，等待同步`：本地学习可继续，显示“重试”按钮。
- `另一台设备已有更新，已载入最新进度`：需要家长知晓刚才未同步操作应重新完成。
- `旧学习进度已永久保存`：首次迁移成功后显示一次明确确认。

登录和“创建全新进度”属于家长操作，入口放在家长中心或首次访问遮罩中，不出现在孩子答题主按钮附近。

## 备份、发布与恢复

- 每天使用 SQLite 一致性备份生成带日期文件，保留最近 30 天。
- 发布前先备份当前应用目录，再对数据库生成一次一致性备份。
- 数据库文件和目录仅授予网站服务账号所需权限。
- 初始化数据库和表结构必须幂等；重复启动不会重置已有数据。
- 应用回滚不得回滚、覆盖或删除数据库。
- 数据恢复只允许在服务器命令行执行：停止写入、校验备份、恢复到临时文件、替换数据库后启动服务并验证；网页不提供恢复按钮。

## 错误处理

- 家庭码错误：保留输入页并提示重试，不泄露服务器状态。
- 会话过期：暂停服务器同步，保留本地数据，要求家长重新输入家庭码；重新登录后继续版本检查。
- 服务器不可用：继续本地保存，显示等待同步和重试入口。
- 数据格式不合法：服务器拒绝写入并保留旧版本；客户端不删除本地快照，提示家长联系维护者。
- 服务器为空且设备无旧数据：阻止空白自动初始化，优先要求使用原设备。
- 版本冲突：服务器数据优先，明确提示重新完成未同步的最后操作。

## 测试与验收

### 自动测试

- 家庭码哈希验证、错误次数限制、设备令牌创建和过期。
- 临时 SQLite 数据库初始化、迁移幂等性和完整状态往返。
- `baseRevision` 正确时版本加一，旧版本写入返回冲突且数据库不变。
- 本地旧数据存在时迁移；服务器为空且本地无数据时禁止自动初始化。
- 离线变更保留最新快照，恢复网络后成功上传。
- 答对后同步进入下一张或完成页，不创建反馈等待计时器。
- 播放读音期间仍禁止提交和跳转；答错进入复习卡并自动读音。
- 原有学习状态列表、搜索、设置、撤销和学习规则回归测试继续通过。

### 用户操作剧本

1. 家长从保存着现有进度的原浏览器进入网站，先记录五个阶段的数量和关键设置。
2. 家长输入家庭码，看到“旧学习进度已永久保存”。
3. 家长刷新页面，确认阶段数量、各字状态、设置和历史仍与迁移前一致。
4. 家长在第二台设备输入同一家庭码，确认看到相同数据。
5. 孩子进入复习，等读音结束后点击“会”，确认下一字立即出现且没有播放上一个字的声音。
6. 家长断开网络完成一次判断，看到“网络断开，等待同步”；恢复网络后点击重试或等待自动同步，看到“已永久保存”。
7. 家长在一台设备修改进度，再让另一台旧页面尝试保存，确认旧页面不会覆盖新进度，并出现冲突提示。
8. 运维人员重启网站服务，家长刷新两台设备，确认进度仍在。
9. 失败恢复：家庭码输错可重试；会话过期可重新登录；误判可用“撤销上一步”；离线可继续并在恢复后重试。
